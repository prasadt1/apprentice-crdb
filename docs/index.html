Apprentice

Teacher corrections live in CockroachDB. Accuracy still falls.

An analyst agent writes SQL against a tiny company sales database. House rules (how this company defines revenue, quarters, and live orders) are not in the schema — they live in CockroachDB memory after a teacher corrects the agent. Ask the same exam question cold, then with memory. Then see what happens when you scale that to fifty questions.

    Why accuracy fell
    
    
    
      The drop is not “memory failed to store.” At full memory, retrieval of the rules the
      gold SQL needed was 44/44. Storage and recall worked. Utilization did not:
      the model over-applies house rules on questions that should stay untouched.
    
    
    
    
      Over-application is real and replicated; it is not monotonic with rule count.
      Both models end below their own unaffected peak — Micro 5/6 → 3/6,
      Lite 6/6 → 4/6. Lite’s worst cell (3/6) is at filters (two rules), not
      at full memory. Micro bottoms at 2/6 mid-curriculum.
    
    
    
    
      k=5 was fixed before the run. With five live rules, retrieval returns
      the whole corpus and ranks nothing. That describes the prompt. It does not fully
      explain the unaffected column.

    How education epochs rewind
    
    
    
      The curve above is four snapshots of the same CockroachDB cluster at four
      Hybrid Logical Clock timestamps — not four restored backups. After teaching, I score
      the exam AS OF each education epoch (memory_zero →
      join_path).
